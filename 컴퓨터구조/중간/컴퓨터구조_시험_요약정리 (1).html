이번 단원에서 배우는 것
아키텍처와 구현은 어떻게 다른가? · 명령어의 입력과 출력은 어디에 있는가?

컴퓨터는 명령어를 읽고 값을 옮기거나 계산합니다. 아키텍처는 프로그래머에게 보이는 명령어와 피연산자의 규칙입니다. 마이크로아키텍처는 그 규칙을 실제 회로로 구현하는 방법입니다. 같은 MIPS 명령어라도 단일 사이클·다중 사이클·파이프라인 구현이 가능합니다.

어셈블리는 사람이 읽는 명령어 표기이고, 기계어는 같은 명령을 0과 1로 표현한 것입니다. 연산 대상인 피연산자는 레지스터, 메모리, 명령어 속 상수(immediate)에서 옵니다.

add $s0, $s1, $s2   # $s0 = $s1 + $s2
sub $s0, $s0, $s3   # $s0 = ($s1 + $s2) - $s3
addi $t0, $t0, -12  # 12 빼기도 음수를 더해 표현

이해를 위한 예시: 레지스터를 작은 작업대, 메모리를 큰 보관함으로 생각하세요. 연산할 값은 작업대에 꺼내 놓습니다. MIPS의 일반 산술 연산은 메모리 값을 직접 피연산자로 쓰지 않고, 먼저 load하여 레지스터로 가져옵니다.

메모리 주소와 엔디안

이번 단원에서 배우는 것
워드 하나의 크기는? · 같은 워드의 바이트가 어떤 순서로 놓이는가?

주소는 보관 위치의 번호이고, 데이터는 그 위치의 내용입니다. C6 p.17–19의 워드 주소 방식은 설명용 모델입니다. 실제 이 교재의 MIPS는 바이트 주소 방식으로, 32비트 워드 하나가 4바이트를 차지합니다.

명령어의미
lw $t0, 12($s0)$s0+12 주소의 4바이트 워드 → $t0
sw $t0, 12($s0)$t0 값 → $s0+12 주소의 워드
lb / sb바이트 하나를 읽기 / 쓰기

이해를 위한 예시: $s0=0x10010000이면 lw $t0,12($s0)은 0x1001000C를 읽습니다. 오프셋 12는 바이트 수이므로 여기에 다시 4를 곱하지 않습니다.

0x23456789를 주소 B부터 저장하면

주소BB+1B+2B+3
빅엔디안23456789
리틀엔디안89674523

16진수 두 자리=1바이트입니다. 빅엔디안은 가장 큰 자리(MSB)의 바이트가 낮은 주소에, 리틀엔디안은 가장 작은 자리(LSB)의 바이트가 낮은 주소에 놓입니다. 워드의 시작 주소 B는 같습니다.

sw $t0, 0($s1)  # $t0=0x23456789, $s1은 유효한 저장 주소
lb $s0, 1($s1)  # big: 0x45 / little: 0x67

기계어: 32비트를 필드로 나누기

이번 단원에서 배우는 것
어셈블리 레지스터 순서와 비트 순서는 같은가? · 음수 즉치값은 어떻게 적는가?

기계어는 명령어의 종류, 레지스터 번호, 상수를 정해진 칸에 넣은 32비트 값입니다. 레지스터 32개 중 하나를 고르려면 5비트(2⁵=32)가 필요합니다.

형식높은 비트 → 낮은 비트대표 예
Rop 6 | rs 5 | rt 5 | rd 5 | shamt 5 | funct 6add, sub, sll
Iop 6 | rs 5 | rt 5 | imm 16addi, lw, sw, beq
Jop 6 | addr 26j, jal

R형의 add는 add rd,rs,rt이지만 기계어는 rs,rt,rd 순서입니다. shamt는 고정 시프트 양이고 일반 add에서는 0입니다. I형의 addi는 addi rt,rs,imm, 메모리 명령은 lw/sw rt,imm(rs)입니다.

필드 채우기 예시

add $s0, $s1, $s2
op=0, rs=17, rt=18, rd=16, shamt=0, funct=32
000000 10001 10010 10000 00000 100000
→ 0x02328020

addi $t0, $s3, -12
op=8, rs=19, rt=8, imm=0xFFF4
001000 10011 01000 1111111111110100
→ 0x2268FFF4
기초 보충: 2의 보수와 부호 확장
n비트에서 음수 −k의 비트 패턴은 2ⁿ−k입니다. −12의 16비트 표현은 65536−12=65524=0xFFF4. 32비트로 부호 확장하면 상위 16비트를 부호 비트 1로 채워 0xFFFFFFF4가 됩니다. 논리 즉치 andi/ori/xori는 상위를 0으로 채웁니다.

비트 연산과 32비트 상수

이번 단원에서 배우는 것
비트를 골라 남기려면? · 오른쪽 이동에서 부호는 어떻게 되는가?
연산비트별 규칙용도
and둘 다 1일 때만 1마스크가 1인 자리만 유지
or하나라도 1이면 1지정한 비트를 1로 설정
xor서로 다르면 1마스크가 1인 자리 반전

32비트 수 두 개를 곱하면 결과가 32비트보다 길어질 수 있습니다. mult는 64비트 곱을 HI(상위 32비트)와 LO(하위 32비트)에 나누어 둡니다. mul rd,rs,rt는 목적지 레지스터에 곱의 하위 32비트를 둡니다.

이번 단원에서 배우는 것
조건이 참일 때 어디로 가는가? · 분기 주소는 어느 PC를 기준으로 하는가?

보통 다음 명령은 PC+4에 있지만 분기는 실행 위치를 바꿉니다. beq는 같으면, bne는 다르면 이동합니다. j는 무조건 목적 라벨로, jr는 레지스터에 적힌 주소로 갑니다.

# if (i == j) f = g+h; else f = f-i;
# $s0=f, $s1=g, $s2=h, $s3=i, $s4=j
bne $s3, $s4, ELSE
add $s0, $s1, $s2
j DONE
ELSE: sub $s0, $s0, $s3
DONE:

if 조건의 반대를 검사해 본문을 건너뛰면 구조가 간단해집니다. 참 분기를 끝낸 뒤 j DONE이 없다면 else 부분까지 실행됩니다. slt rd,rs,rt는 rs<rt일 때 1, 아니면 0을 저장합니다. a>b는 b<a로 바꾸면 됩니다.

★★★ 제작자 선정 학습 핵심
분기 목적지 = PC+4 + (부호 확장한 imm × 4)
imm = (목적지 − (PC+4)) / 4

이해를 위한 예시: PC=0x1000, 목적지=0x1010이면 imm=(0x1010−0x1004)/4=3. 뒤로 분기하여 목적지가 0x0FF8이면 imm=−3입니다. 조건이 거짓이면 imm와 관계없이 다음 PC는 0x1004입니다.

j의 목적지는 {(PC+4)의 상위 4비트, addr 26비트, 00}입니다. 26비트를 왼쪽으로 2비트 이동하여 28비트로 만든 뒤 상위 4비트를 붙입니다. jr는 이 조립을 하지 않고 레지스터의 주소를 사용합니다.

F:

이번 단원에서 배우는 것
j를 어떻게 추가하는가? · CPI가 같아도 속도가 달라지는가?

j 확장: C7 p.31은 addr를 2비트 왼쪽 이동하고 PC+4의 상위 4비트를 붙인 PCJump를 만듭니다. 마지막 PC 선택기에 Jump 신호를 추가합니다. j는 RegWrite=0, MemWrite=0, Jump=1이며 기존 분기 경로의 선택값은 결과에 영향을 주지 않습니다.

실행 시간은 실제 수행 명령 수(IC) × 평균 CPI × 클럭 주기(Tc)입니다. Tc=1/f이며 IPC=1/CPI입니다. 단일 사이클이면 CPI=1이지만 그 한 사이클이 충분히 길어야 합니다.

★★★ 제작자 선정 학습 핵심
총 사이클 = Σ(종류별 실행 횟수 × 그 종류 CPI)
평균 CPI = 총 사이클 / 총 실행 명령 수
실행 시간 = 총 사이클 / 주파수
속도 향상비 = 이전 실행 시간 / 이후 실행 시간

이해를 위한 예시: ALU 명령 6개(CPI 1), load/store 2개(CPI 3)를 실행하면 12사이클, 평균 CPI=12/8=1.5입니다. 2GHz면 1사이클=0.5ns이므로 6ns입니다. 단순히 (1+3)/2로 평균 내면 안 됩니다.
